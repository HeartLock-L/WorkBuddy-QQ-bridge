# QQbot 部署指南

更新：2026-10-27。组件为 WorkBuddy 桌面版、AstrBot、NapCat 与 workbuddy_bridge 插件。本仓库提供插件和配套脚本，不附带第三方程序、Python 环境、账号、网关凭据或聊天记录。

本次更新调整了模型问答通道：所有问答改走本机网关的任务通道（发布任务 + 流式读取），不再使用旁问接口。好处是模型手里有完整工具，能看图、能自己联网查；代价是这些请求会进入管理员桌面上正在使用的同一个会话，管理员本人正在对话时，群消息会排队等待（单条上限 240 秒）。

## 一、能力与边界

| 能力 | 说明 |
|---|---|
| 群聊 | 群里 @、引用机器人消息或命中配置的唤醒入口后自动回答；闲聊、跟随及关键词冒泡受各自开关与节流限制 |
| 私聊 | 仅管理员；其他成员在群内使用 |
| 普通聊天 | 走本机网关的任务通道，用一次性回执码只回传属于本次请求的产物 |
| 操作任务 | 管理员用“/执行 任务内容”或“执行任务 任务内容”显式发起；其他成员请求先待审批，由管理员在原群回复“同意”后执行 |
| 角色扮演 | “扮演 xxx”开始、“出戏”结束，按群保存状态并受超时限制 |
| 生图 | 可选即梦 CLI，默认对所有群友开放（可在面板改回仅管理员），受冷却、全局间隔及每日上限限制 |
| 附件理解 | 可读图片：收到的图先落盘，再把本地路径交给模型打开；支持“先 @ 说要看图、随后补发图片”的跟进，补发消息不带 @ 也算 |
| 联网搜索 | 插件自身按关键词预搜公开网页，把结果拼进提示词；模型侧不额外授予工具权限 |

任务通道意味着**不隔离**：群里的每一次问答都是这台机器上一个真实的 agent 任务，能读写文件和执行命令。因此提示词里对普通群友设了只读约束，但那是约定而非系统级沙箱；要接陌生群，请先想清楚这一点。

获批任务只收集本次任务独立目录的文件，避免同一用户在不同群并行执行时混发附件。execute 的产出目录只是提示词约定，尚无操作系统级沙箱；不能保证执行工具无法访问目录外的文件。启用和审批前请据此判断任务是否适合在这台机器执行。

即梦核心在 `workbuddy_bridge/jimeng.py`，由主插件调用本机已有的 `dreamina.exe`，无需启动即梦反代网页服务。安装时保留原 CLI 路径和登录状态，并保留插件中的 `draw_sessions.json`，避免丢失一人一框的映射。`image_jobs.py` 保存任务状态，升级时还需保留同目录的 `draw_jobs/`；任务记录含请求来源和描述，仅保存在本机，不进入部署包。

## 二、准备软件与目录

需要 Windows、已登录并保持运行的 WorkBuddy、机器人 QQ 号、手机扫码登录，以及能运行所选 AstrBot 版本的 Python 环境。原材料基于 AstrBot v4.28.2、NapCat v4.18.28，安装依赖和 QQ 内核兼容性以对应版本说明为准。

官方下载与说明：

- [AstrBot](https://github.com/AstrBotDevs/AstrBot)
- [NapCat](https://github.com/NapNeko/NapCatQQ) 与 [Windows 部署文档](https://napneko.github.io)
- [Python](https://www.python.org/downloads/)

建议目录如下：

~~~text
<项目根>\
├─ AstrBot\main.py
├─ AstrBot\data\plugins\workbuddy_bridge\
├─ NapCat\NapCatShell\
├─ NapCat\QQNT\Files\QQ.exe
├─ .venv\Scripts\python.exe
├─ 即梦反代\dreamina.exe        可选
└─ 本仓库的 start-*.bat、scripts、docs 与 tests
~~~

## 三、安装步骤

### 3.1 放置 AstrBot

把官方源码放在项目根的 AstrBot 目录，确认 AstrBot\main.py 和对应版本的 requirements.txt 存在。第三方代码不用从本仓库复制。

### 3.2 创建本机 Python 环境

在命令提示符中执行，路径按本机修改：

~~~bat
cd /d D:\QQbot
python -m venv .venv
.venv\Scripts\python.exe -m pip install --upgrade pip
.venv\Scripts\python.exe -m pip install -r AstrBot\requirements.txt
.venv\Scripts\python.exe --version
~~~

如果虚拟环境启动器不能创建进程，先修复或重建本机环境；不要直接复制别的机器的 .venv。源代码和配置备份不等于可跨机器使用的解释器。

### 3.3 放置 NapCat

按所选 NapCat 版本的官方说明安装。要使用本仓库的 start-napcat.bat，请整理为：

~~~text
<项目根>\NapCat\NapCatShell\napcat.mjs
<项目根>\NapCat\NapCatShell\NapCatWinBootMain.exe
<项目根>\NapCat\NapCatShell\NapCatWinBootHook.dll
<项目根>\NapCat\QQNT\Files\QQ.exe
~~~

也可以用官方启动方式；后续仍需把反向 WebSocket 连到 AstrBot。

### 3.4 复制本仓库文件

1. workbuddy_bridge 整个文件夹复制到 <项目根>\AstrBot\data\plugins\ 下，清单中的全部源码模块必须一起更新。
2. 仓库根目录的 start-astrbot.bat、start-napcat.bat、scripts、docs 与 tests 复制到项目根，保持目录层次。

复制插件后，在项目根安装其依赖（GIF 读取使用 Pillow）：

~~~bat
.venv\Scripts\python.exe -m pip install -r AstrBot\data\plugins\workbuddy_bridge\requirements.txt
~~~

插件源码包括 main.py、bridge_policy.py、draw_flow.py、proactive_chat.py、memory_store.py、memory_service.py、prompts.py、reply_text.py、attachments.py、meme_library.py、meme_collection.py、cache_maintenance.py、runtime_status.py、source_files.py、jimeng.py、image_jobs.py、image_job_commands.py、request_queue.py，完整清单由 source_files.py 维护。维护工具还需包含 scripts/diagnostic_evidence.py 和 scripts/reset-astrbot-password.py。只更新 main.py 无法得到完整修复，运行数据文件仍按下文保留。

默认运行包包含 bridge_selftest.py 和 selfcheck 子目录；开发包另含完整开发回归。已有完整开发测试的项目应使用开发包更新，避免保留旧测试却只更新运行代码。scripts/test-bridge.bat 会明确显示当前目录能运行的检查范围。

### 3.5 设置身份与路径

编辑插件 bridge_policy.py（身份、群规则与业务默认值集中在此）：

~~~python
MASTER_ID = "0"       # 改成管理员 QQ；不要填机器人 QQ
EXPECTED_SELF_ID = "" # 建议填写机器人 QQ，登录错号时拒绝处理
~~~

管理员可以接收私聊、审批操作任务并使用管理命令。其他成员只能在群里使用，私聊不接入模型。自动 AI 聊天和生图保持原有使用方式；涉及本机操作的任务继续走管理员审批。

项目根优先读取 QQ_BOT_ROOT，再从插件位置推导；即梦 CLI 可通过 QQ_BOT_DREAMINA 指定，也可放在项目根的“即梦反代”目录。一般部署不需要改源码里的盘符。

材料中的群号、对象账号与群梗词是示例。需要时自行填写 GROUP_GAG_RULES；不用则置为空字典。不要把旧材料示例误认为自己的正式配置。

### 3.6 配置 QQ 消息连接

先启动 start-astrbot.bat，打开 http://127.0.0.1:6185。用户名、首次随机密码以本机启动输出为准；忘记密码使用 scripts/reset-astrbot-password.bat。

在 AstrBot 中添加并启用 QQ / aiocqhttp / OneBot v11 适配器，反向 WebSocket 端口为 6199。同机部署将监听地址设为 127.0.0.1；当前配置对应 ws_reverse_host 和 ws_reverse_port，修改后重启 AstrBot 生效。跨机器部署需按实际连接方式与对应版本说明设置访问范围。

启动 NapCat，在其 WebUI http://127.0.0.1:6099/webui 中添加或确认 WebSocket 客户端：

~~~text
ws://127.0.0.1:6199/ws
~~~

访问令牌从本机 NapCat 启动输出获取；若配置连接鉴权，两端必须一致。用机器人账号扫码，确认 AstrBot 显示适配器已连接。面板和接口不要直接映射公网。

### 3.7 初始化 WorkBuddy 网关

保持 WorkBuddy 打开，并在该项目的会话内让它执行：

~~~bat
.venv\Scripts\python.exe scripts/reconnect.py
~~~

脚本优先使用会话注入的环境凭据，再尝试已有凭据及本机端口；认证成功后保存 workbuddy-gateway.env。不要把这个文件发给其他人。

首次部署 AstrBot 尚未启动时，凭据写好后也可能返回 UNKNOWN，表示插件恢复尚未确认。此时按下节启动并验收，而不是把 UNKNOWN 当成全部成功。WorkBuddy 重启或凭据变化后，可以再次重连；外部脚本若拿不到新密码，需要回 WorkBuddy 项目会话刷新。

## 四、启动与完整验收

1. 保持 WorkBuddy 已登录、运行。
2. 启动 start-astrbot.bat，保留窗口。
3. 启动 start-napcat.bat，机器人账号扫码；确认 OneBot 连接。
4. 运行 scripts/doctor.bat，根据 PASS、FAIL、UNKNOWN 处理。
5. 运行 scripts/test-bridge.bat，确认显示的是完整开发回归或部署自检，并检查结果（不联网、不耗额度）。真实模型链路直接在群里 @ 一句验收，会消耗 WorkBuddy 额度。
6. 分别在两个测试群 @ 机器人，核对回答只出现在被 @ 的那个群、内容对得上本条问题；另确认普通成员私聊不调用模型。
7. 用同一位测试成员发送“看图”请求后补图，再由另一位成员发图；确认只跟进原请求人的图片。引用图片时也核对作者与来源。
8. 发起一次生图请求，确认只在原群交付一次；分别验证普通图送达后本地副本清理、机器人自拍保留；等待任务完成后再重载插件，检查版本、心跳和普通问答恢复。
9. 在两个测试群同时发送不同附件，核对来源不混用；发送普通 GIF、超过 10 MiB 的附件以及合计超限的多附件，检查抽帧理解和拒绝提示。
10. 在测试群 @ 后查询生图任务；只对测试任务核实后执行管理员处理，检查普通成员不能处理、补发仅回原群。
11. 普通成员提出示例操作请求，确认进入待审批且没有执行；管理员回复“不行”后确认该请求取消。
12. 在两个测试群分别明确 @ 机器人，核对即时文字回复引用各自本条提问，不引用提问中转引的旧消息；检查 @全体、戳一戳与管理员私聊不添加这种引用，关闭引用开关后恢复普通回复。
13. 放入一张已确认内容的人工表情，在测试群发送 QQ 自定义表情和普通图片，检查仅带表情标记的图片被收藏；另一群不能使用该群的收藏。轻松聊天中观察配图或纯表情回复，不以每轮都发图作为通过条件；首次看图后检查名称标签能在重载后保留，后续相关话题可按名称召回；关闭表情总开关后不再配图或收藏。


问答走任务通道后不再有会话隔离：同一条问题会作为一个真实任务落在管理员桌面上。验收时要关注的是“回没回到正确的群、内容有没有串”，而不是“有没有隔离”。

## 五、使用、运维与编码

群里可 @ 机器人提问，角色扮演可说“扮演 一个话很少的剑客”，结束说“出戏”。其他唤醒入口和主动开口能力受各自面板配置约束；生图保持原有触发与权限规则，操作任务继续管理员审批。

管理员的普通消息同样不自动授权执行。要动手执行，请发送“/执行 任务内容”或“执行任务 任务内容”。批准其他成员的待审批任务时，在该任务的原群回复“同意”。管理员私聊可管理上下文、使用代发命令。群内的配置与部署问题可提示管理员转私聊；普通成员不会因此获得私聊入口。

### 引用回复与自动表情

群友明确 @ 机器人后，即时文字回复默认携带 QQ 原生引用，使用本条提问自己的 `message_id`，不使用被引用的旧消息编号。@全体、私聊、戳一戳、无有效消息标识或无法构造引用时普通回复；主动闲聊和异步生图结果沿用原发送路径。此功能便于定位问题，不提供额外的模型会话隔离。

人工素材放在项目根的 `表情包/` 顶层，建议用简短文件名描述内容，各群均可使用。支持 JPG、JPEG、PNG、GIF、WebP、BMP，单图不超过 10 MiB。自动收藏保存在 `表情包/自动收集/<会话摘要>/`，只提供给原会话；不保存作者或聊天正文。仅收取群消息中 QQ 标为自定义表情的直接图片，即 `sub_type=1` 或 `file=marketface`，不收普通图片、引用或转发里的图片、私聊及机器人自己发送的图片。这是消息类型识别，不是视觉分类：照片若作为自定义表情发送，也会被视为表情。

自动收藏同群至少间隔 5 秒，最多两个后台收取任务；按内容去重，每群最多 100 张，全局最多 500 张且合计不超过 100 MiB，单张仍限 10 MiB。重复出现会刷新保留时间，30 天未再出现的收藏定期清理；人工素材不参与这套清理。

符合条件且未在冷却时，按当前消息与本群近期话题匹配已确认的名称、情绪和用途标签，最多提供三张候选，取消原来的 20% 随机门槛。每轮最多提供一张未命名图进行只读识别，候选图像读取总量不超过 10 MiB；模型看清后自动起简短名称、记录用途标签，下次优先依据已确认的名称标签选择，无需反复看同一张图。命名复用本次 WorkBuddy 请求，不额外发起模型任务，也不让模型直接改文件。

名称索引保存在各图片目录的 `.names/<图片指纹>.json`，例如记录“猫猫疑惑”与“疑惑、没听懂”标签；原图片文件名保持稳定，继续用于去重。索引只保存画面含义与使用场景，不保存群友身份或聊天原文。收藏图与索引仍局限原会话，图片过期或淘汰时同步清理名称；手工库不参与自动收藏清理。

是否发送由同一次模型请求结合语境判断：轻松短互动可以只回表情或配一句短话，解释、求助等认真问题仍需文字回答，没合适素材就不硬发。每次最多一张，明确静默、失败、过滤后无有效文字及过期主动回复不使用表情兜底；合法的纯表情选择另行校验。发送前重新核验来源、文件和冷却，结果不明时不自动重发。默认同群间隔 120 秒、全局间隔 20 秒、同一图片 10 分钟内不重复。已有面板配置不会被覆盖；若以前保存过 600 秒，可把 `meme_cooldown_sec` 调至 120 秒。

| 面板配置 | 默认值 | 作用 |
|---|---|---|
| `quote_reply_enabled` | 开启 | 明确 @ 机器人时引用本条消息 |
| `meme_enabled` | 开启 | 自动表情总开关，关闭后也不再收藏 |
| `meme_collect_enabled` | 开启 | 自动收藏同群 QQ 自定义表情 |
| `meme_cooldown_sec` | 120 秒 | 同群配图间隔，允许 60–3600 秒 |

### 维护工具

| 工具 | 用途 |
|---|---|
| scripts/doctor.bat / scripts/doctor.py | 语法、离线逻辑、运行指纹、认证、端口与进程检查；会生成 Python 缓存或临时测试文件 |
| scripts/reconnect.bat / scripts/reconnect.py | 刷新凭据并尝试重载；完整成功需确认插件的新实例 |
| scripts/reload-plugin.bat / scripts/reload-plugin.py | 外部重载救援，检查本次实例与源文件指纹 |
| scripts/pause-bridge.bat / scripts/resume-bridge.bat | 暂停与恢复 QQ 桥接，适合维护和编辑期间使用 |
| scripts/reset-astrbot-password.bat / .py | 核实精确 6185 端口属于本项目后终止并重启重置；身份不明拒绝 |
| scripts/fix-bat-encoding.bat / .py | 按脚本意图修复编码与 CRLF，保留 chcp，保留原件备份 |

**结果含义：** PASS 或 VERIFIED 只表示对应检查有证据通过；FAIL 是确认失败；UNKNOWN 是证据不足。运行指纹过旧、没有新实例标记或日志不可读都可能得到 UNKNOWN。doctor、reconnect、reload-plugin 的退出码分别为 0（已确认）、1（失败）、2（UNKNOWN）。即使返回 0，仍需用 QQ 测试消息验收收发。

**热重载：** 面板开启后，保存 source_files.py 清单中的任一源码文件可触发重载，包括 prompts.py 和 reply_text.py；也可使用 scripts/reload-plugin.bat 检查重载结果。若语法错误使插件无法加载，外部脚本仍可用于修复后的重载；仅看到面板接口已受理不代表代码生效。

**安全重置密码：** 仅核验属于本项目的 Python 与绝对 AstrBot\main.py 启动路径后才能终止。旧启动方式使用相对 main.py 时会拒绝；请手动关闭正确的 AstrBot 窗口后再运行。之后 start-astrbot.bat 使用绝对脚本路径。

**BAT 编码例外：** 纯 ASCII+CRLF 最稳妥；中文脚本可以使用 GBK+CRLF；若先以 ASCII 指令 chcp 65001 切换代码页，再出现非 ASCII 内容，则可保留 UTF-8+CRLF。不要无条件删除 chcp，也不要把带 UTF-8 切换的脚本强制转成 GBK。修复工具会拒绝混用代码页、过晚切换或不能无损编码的情况，原文件留存于日期备份目录，重复修复不会覆盖早先原件。

## 六、可选生图与附件限制

即梦生图走插件独立的 CLI 分支。把可用且已登录的 dreamina.exe 放在约定位置或设置 QQ_BOT_DREAMINA，再按面板配置使用人、冷却、模型及每日上限。默认对所有群友开放，想收紧就在面板把“仅管理员”打开。支持的模型和服务额度以本机 CLI 实际结果为准；没有安装时可关闭生图总开关。

生图按 QQ 号复用同一个即梦会话（一人一框），并发到同一人时第二张会被挡下并回一句提示。同时处理的生图任务最多两个，每个任务使用独立下载目录。

生成超时涵盖会话准备、提交、查询和下载，重载不会重新计时。拿到任务号后仅查询原任务，查询临时故障不重新提交。原时限内可恢复未完成查询；已生成图片在 24 小时内恢复投递，明确发送失败最多尝试三次。发送异常、提交结果不明时停止自动重试并保留记录，不保证在网络确认丢失时自动补发。暂停、账号尚未验证或生图关闭时不恢复任务。改名放在成功回图后执行，不影响交付。

热重载会通知 CLI 线程停止并等待当前有界调用结束后释放任务锁，等待最多约 30 秒的单次 CLI 时限。任务记录的 `state` 区分 queued、submitted、ready、delivered、failed、expired、submission_unknown 和 delivery_unknown。排查时可在本机查看 JSON；不要删除任务记录后盲目重画，也不要将记录发到群里。

图片属于可用能力：收到的图先落到本地缓存，插件把路径写明发给模型，由模型自己打开看。只认提问者本人近期发过的图，不会拿别人的图来答；先 @ 说要看图、几十秒内补发图片的跟进也支持。语音与其它文件格式没有可靠保证，不要当成已验证能力。缓存路径本身不等于模型读到了内容，判断是否真的读了要看回答里有没有具体信息。

本地生图保留规则：只有机器人“你的照片/自画像”专用入口生成的自拍长期保留，新任务在提交前保存不可变的保留标记。普通图正常送达、管理员确认已送达、人工补发成功或管理员结束记录后，清理该任务记录指向的本地图片。发送失败或结果不明时先保留，超过任务原有的 24 小时恢复窗口后，在后续每小时维护中轮转清理；每轮最多检查 100 条，锁仍被工作进程占用时跳过。本地清理失败不改变已送达状态，后续维护会重试。

只清理配置生图根目录下独立任务文件夹中的已登记图片，拒绝链接、重解析路径和越界位置；只回收空任务目录。自拍、其他任务结果及未登记文件不删除。旧任务依照准确的自拍提示词前缀识别；没有任务记录的旧平铺图不猜测分类，因此暂时保留。更改生图目录后需重载插件。

清理本地副本不删除即梦网页端内容，也不发起远端删除操作；网页端的可用性与保留期以服务本身为准。任务记录、原始路径和远端标识保留，并标记“本地副本已清理”。此后查询会显示清理状态，补发不会自动重新生成，需到即梦网页查看原图。

附件单文件与单条消息累计原始附件均不得超过 10 MiB（10 × 1024 × 1024 字节，聊天提示写作 10 MB），最多读取 5 个。单个附件取文件最多 15 秒，整批处理预算 30 秒；大小、超时和解析失败会直接提示。已有成功附件时继续读取成功部分，全部失败时不调用模型假装读过。来源信息跟随每条请求保存，互不覆盖，也随待审批任务一起保留。

普通附件最初取文件由框架完成，能拿到大小声明时提前拦截，返回本地文件后再次校验并进行有界复制；框架自身的临时下载行为没有改动。闲聊读图由插件下载，响应声明和实际流量都限制为 10 MiB。

GIF 按文件内容识别，保留原文件并生成最多 8 帧的时序拼图。每张 GIF 最多解析前 200 帧，单帧最多 400 万像素、累计解码最多 4000 万像素，先到限制就停止抽样并标明范围；超大单帧拒绝。生成的预览另限 1 MiB，不占原始附件额度。预览按从左到右、从上到下排列，包含帧号；这是抽帧理解，不能保证看全动作或判断精确速度、时长。依赖缺失或动图损坏时明确报错。安装或手动更新插件后，请在运行 AstrBot 的 Python 环境安装插件 `requirements.txt` 中的 Pillow。

生图任务命令沿用原有唤醒和权限规则：群内先 @ 机器人，再发送命令。

| 命令 | 行为 |
|---|---|
| `/生图任务` | 查看本会话未归档任务，待确认和进行中的优先，最多显示 10 条；普通成员仅见自己的任务 |
| `/生图任务 任务号` | 查看状态，可使用列表中的短任务号；同前缀有冲突时需使用完整任务号 |
| `/生图处理 任务号 确认已送达` | 管理员核实图片已经收到后，将“发送结果待确认”标记为送达 |
| `/生图处理 任务号 补发确认` | 管理员确认需要补发后，只将原任务已有图片发送到原会话；不会重新生成 |
| `/生图处理 任务号 结束` | 管理员结束未完成记录，保留自拍、清理普通图本地副本；不终止仍在运行的远端任务 |

管理员也只能在任务原会话管理它。正在提交、生成或发送的任务暂不能人工处理；“提交结果待确认”不会因为补发指令重新生图。补发要求可核对的消息标识，同一条指令持久去重，每个任务最多人工补发三次。发送超时或异常保留待确认状态；插件停止时取消人工操作，重启后按不确定结果处理，不盲目再发。

维护每小时轮转检查最多 100 条任务记录，已送达、失败、过期、人工结束且最后更新超过 30 天的记录移至 `draw_jobs/archive/年月/`。原始 JSON 保留，归档冲突不覆盖；活跃任务和结果不明的任务记录保持原处，图片按下述规则独立清理。锁文件不删除，保证其他进程看到同一把锁。聊天查询不扫描归档，需要历史记录时在本机查看。

缓存维护在插件加载后执行一轮，此后每轮结束间隔一小时自动执行；不依赖群里有人发言，也不受主动闲聊开关影响。收到的附件保留两天，媒体缓存保留一天，两类保留策略独立处理。

媒体清理范围仅为 AstrBot/data/temp 的顶层文件和 idle_pics 子目录直属文件，每轮合计最多删除 2000 个过期文件，不删除目录。其他子目录、最近一天的文件、用户产出以及链接或重解析路径均跳过。日志中的 managed_remaining 统计同一维护范围，不能用它判断整个 temp 目录树大小。重载或退出时会通知删除线程停止并等待结束。

## 七、离线回归与材料更新

优先在项目根运行 scripts/test-bridge.bat，它会按当前包的内容选择检查范围。源码目录或开发包也可以分开运行：

~~~bat
.venv\Scripts\python.exe -m unittest discover -s tests -p "test_*.py" -v
.venv\Scripts\python.exe tests/bridge_selftest.py
~~~

离线回归使用桩与临时目录，不连接 QQ 或真实模型，不终止真实进程。维护暂停标记在逻辑自检中默认隔离。真实链路只能靠群里发一条消息验收，会消耗额度。

两种包都保留部署自检，入口为 tests/bridge_selftest.py，功能检查位于 tests/selfcheck/。开发包额外提供生图、产出归属、回执校验、生命周期、诊断及运维工具的完整回归。构建器测试只供维护者使用，两种包都不包含 build-material.py，开发包中对应测试会明确跳过。


维护者在最终源码合并后运行 scripts/build-material.py 生成 QQbot部署材料；加 --development 生成独立的 QQbot开发材料。两者都统一复制、脱敏、验证，输出到 dist/ 下的目录及 ZIP。构建脚本本身保存真实值到占位值的对照，因此不分发。不要把本机凭据、日志、缓存或聊天导出放进材料。构建校验提供一道防线，不代表所有未知敏感信息都能被自动识别。

## 问答队列与故障恢复（2026-10-28）

网关使用动态端口：优先认证配置中的地址与上次成功地址，失败后才扫描本机回环端口。30 秒失败退避只阻止重复全量扫描，不阻止已知地址重试；配置端口或凭据变化可立即重新扫描。重启若同时更换密码，需要 WorkBuddy 当前会话提供新凭据，扫描本身不能获得新密码。

所有 QQ 模型请求统一排队，一次只提交一个任务。普通提问和已审批操作同级、先进先出，不再先等待各群独立的锁。默认最多 5 条等待、每条等待最多 60 秒；队列满或过期的请求没有提交到 WorkBuddy，不会在后面悄悄执行。配置项为 question_queue_limit 与 question_queue_wait_sec，修改后重载生效。

冷场、跟随、关键词冒泡和自动锐评只在空闲时调用模型；忙时跳过，自动锐评可用原有固定短句。主动内容默认 30 秒时效（proactive_reply_ttl_sec），涵盖取材、连接、生成和回复检查。发出前还会核对本群消息版本，群里出现新消息或有真人请求等待时丢弃过时内容。已开始的远端任务不能被本地抢占。

日志中的 [question] 按 admission/outcome、wait_ms/service_ms 记录排队和处理耗时，不记录提示词。主动静默、回执校验失败、排队超时和连接失败分别识别。回执只用于确认回复归属，不隔离 WorkBuddy 的模型上下文。

question_run.json 保存尚未明确结束的远端任务编号，question_run.lock 用于防止新旧插件实例同时提交。更新插件时保留这两个本机状态文件，部署包不携带它们。本地超时、断线或重载后，只有查询明确返回已结束，才会清除占用。查询失败、无法获取任务号或网关地址改变时不自动重提。

如果提示“上一条任务的状态还没确认”，管理员先在 WorkBuddy 确认上一轮已经结束，再发送：/恢复问答 确认上一轮已结束。该操作只清除本机占用，不会取消远端任务；非管理员、缺少明确确认或当前仍有本机请求处理时均不会清除。

连续网关错误触发主动闲聊暂停后，普通问答在回执有效、远端明确结束且占用成功清除后会自动恢复闲聊。执行类任务、排队跳过和错误回复不算恢复证据。

bridge_status.json 是仅本机使用的运行快照，每 30 秒更新，退出时写入 stopped。doctor 分别报告存活、版本、动态网关认证和问答状态；快照有效期为 90 秒。历史版本一致不能证明当前存活，认证通过也不能证明模型已回答或 QQ 已收到消息。队列状态区分未提交成功、网关地址变化、记录不可读和仅有旧任务记录等原因，不能根据新端口出现就自动清空旧任务。状态仅含固定类别与计数，不含聊天正文、群标识和凭据，不进入分发包。

## 长期记忆

长期记忆由桥接层独立管理，保存在插件目录的 `memory.sqlite3`，不依赖 WorkBuddy 的会话保存；数据库及其 WAL/SHM 文件，以及本机的 `memory_control.json`、`memory_control.processing.json` 控制请求，都不随部署包分发。记录以平台实例、机器人账号和群聊/私聊为第一层，以发言成员为下一层。同一个人在不同群不自动共享，昵称变化不改变归属。每个群保留有来源支持的共同话题、活动或约定，成员的偏好和个人近况保存在该群下的独立记忆里。普通问答只召回提问者本人的资料及相关群记忆；主动闲聊按人物标注相关同群资料。记忆不改变管理员身份和执行审批。

查看群层目录用 `/群记忆`，展开共同主题用 `/群记忆 主题名`，全部群条目用 `/群记忆 全部`；群目录显示简短介绍和成员记忆统计，不展开别人的个人档案。查看自己在当前群的子目录用 `/记忆`，展开主题用 `/记忆 主题名`，查看全部个人条目用 `/记忆 全部`。内容较多时按提示加页码，例如 `/群记忆 目录 2` 或 `/记忆 饮食偏好 2`。正常聊天无需这些命令；明确补充可在原群 @ 机器人后发送 `记住：我不吃香菜`，更正用 `/更正记忆 编号 新内容`，删除用 `/忘记记忆 编号`，清除本人的原文和记忆用 `忘掉我的全部记忆`。个人命令只操作本人；群记忆由后台按来源整理，不通过这些个人命令直接写入。`/重置` 仍只重置聊天上下文。

消息先收录、后整理：每次收到可确认来源和消息标识的人类消息，先按群、成员、原消息时间和接收时间写入 SQLite，同时用本地规则标注消息类型（闲聊、问句、命令、媒体、角色扮演或超长）和主题线索（偏好、计划、自述或其他）。这些标签只是原消息分类，不等于已核实的长期事实，不调用模型，也不会直接生成记忆。schema 4 为旧记录补充中性默认标签，原文、可提炼标记和遗忘屏障保持不变。每条文字最多保留 1000 字，原文保留七天，每个会话最多 2000 条；命令、角色扮演和超长片段可保留为非提炼记录。纯媒体消息只记类型占位，不为记忆额外下载附件。角色状态检查不会因普通群聊而续期。

模型整理只能由管理员手动开启，平时只收录、分类和召回已有记忆。QQ 入口为 `/整理记忆 开始`、`/整理记忆 停止`、`/整理记忆 状态`；本机入口为 `scripts/memory-control.bat --start`、`--stop`、`--status`，对应 Python 脚本也接受相同参数。每次开启只处理启动时已经积压的消息；之后收到的新消息继续入库，留给下次手动整理。本轮完成后自动结束，重载或重启不会自行恢复模型整理。

启动前，管理员先确认其他 WorkBuddy 窗口没有任务。程序会检查本插件的问答、生图和待审批任务，以及当前网关的状态；每批提交前再检查一次。现有公开接口不能保证全桌面所有会话在同一时刻均空闲，因此不能仅凭本插件队列为空就断言全局空闲。有新的前台任务时结束本轮，由管理员在空闲后重新开启；停止请求不会强杀已提交的远端批次，会保留跟踪并在当前批次收尾后停止。

每批以一名成员的待整理原话为主，并附同一群按时间排列的相邻发言；两者都受本轮启动时的消息上界限制，明确标注作者与时间。一次请求同时筛选个人记忆和群记忆，沿用原有 WorkBuddy 队列与普通聊天权限。整理使用专门的内部 JSON 提示词，不套用 QQ 聊天人设、静默或先搜索规则；一次性回执和当前批次的 proof 分别校验。来源文字只作材料，不授予工具或电脑操作权限。没有候选也必须返回带正确 proof 的空数组。

个人事实不再要求以“我／本人／叫我”开头，但仍必须由本人完整原话支持；问题、假设、转述和指向其他人的内容不能直接写成本人事实。群记忆需要至少两名成员的原话支持，不把单人的喜好当作全群共识。内容保存经核验的完整原话及必要上下文来源，不接受模型凭空改写的事实；每条事实原文不超过 300 字，不确定或无长期价值时跳过。原始待办和退避时间持久保存，重启后仍需管理员重新开启一轮整理。

整理诊断区分保存成功、合法空候选、候选被过滤或无变更，以及网关、忙碌、状态待确认、静默、格式与证据校验失败；零条入库也记录固定结果类别和计数，不再把这些情况统一归为 JSON 格式错误。本机 `bridge_status.json` 的 `memory` 摘要提供整理状态、尝试和保存计数、最近一批的结果与过滤原因计数；只接受白名单状态和数值，不含聊天原文、记忆内容或成员身份。计数从本次插件启动开始；若提交途中被取消、结果尚未确认，省略无法确认的保存数，不把它记成零。消息收录数量不等于长期记忆数量，心跳摘要也不能代替数据库库存核对。

群记忆和个人记忆均可按主题归组，每组有一句简短介绍，依据当前有效条目生成并参与检索。更正、遗忘或到期后介绍同步更新，空组自动消失。同组不同事实有独立专题，不相互覆盖。数据库自动迁移现有记录，无需重建。

保存期限分为稳定偏好、稳定自述和近期话题；近期话题七天过期，稳定资料保留至更正或遗忘，每个会话最多 500 条有效记忆。更正保存修订，明确保存的个人条目不被自动整理覆盖。遗忘会删除相应内容、证据和修订，并清除本人的旧原文；依赖这些原话的群记忆和上下文引用也失效，旧批次不能重新写回。每小时清理过期原文和话题。面板 `memory_enabled` 控制采集和召回；关闭后仍可查看和忘记已有记忆。`memory_auto_extract` 仅作为历史配置兼容保留，默认关闭，即使旧配置仍为 true 也不会自动发起模型整理。数据库异常时记忆功能退避一分钟。以上会话范围只覆盖桥接层提供的资料，不改变 WorkBuddy 内部上下文行为。

验收时用两个群的同一账号分别保存不同偏好，确认只在原群召回；重载后再次询问；更正后只使用新内容；遗忘后再次询问不能从旧原文恢复。另用自然聊天中的完整陈述验证：先确认原文已分类收录且未自动发起模型任务，再由管理员在空闲时手动开启整理，检查结果与原群目录；合法空候选和规则过滤不算保存成功。手动开启后的模型整理依赖 WorkBuddy 返回规定格式，更新后仍需观察真实链路的实际产出和成功率，离线检查通过不代表线上已生成记忆。无需手工创建数据库，也不要把本机记忆放进部署包。新面板选项缺失时使用代码默认值，保存一次面板可由框架补齐。
