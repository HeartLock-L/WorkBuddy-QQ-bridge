# QQbot 本地桥接

WorkBuddy 负责理解和回答，AstrBot 与自制插件处理消息，NapCat 负责 QQ 收发，即梦 CLI 负责生图。目录整理日期：2026-10-28。

## 目录

```text
QQbot/
├─ start-astrbot.bat           启动 AstrBot
├─ start-napcat.bat            启动 QQ / NapCat
├─ scripts/                   维护工具和打包脚本
├─ docs/                      部署指南、使用规则和优化建议
│  └─ 历史记录/               历次检查报告与规则清单
├─ tests/                     当前有效的离线测试
├─ dist/                      生成的部署材料与 ZIP
├─ backups/                   旧备份与本次清理前的恢复包
├─ AstrBot/                   框架及 workbuddy_bridge 插件
├─ NapCat/                    QQ 接入程序
├─ .venv/                     项目 Python 环境
├─ 表情包/                    人工素材与按群隔开的自动收藏
├─ 收到的附件/                消息附件
├─ 用户产出/                  任务结果及生成图片
└─ workbuddy-gateway.env       本机网关凭据，不分发
```

运行程序和数据目录保留原位置。插件位于 `AstrBot/data/plugins/workbuddy_bridge/`，按职责维护：

| 模块 | 职责 |
|---|---|
| `main.py` | QQ 入口、生命周期、权限与问答调度 |
| `bridge_policy.py` | 身份与业务默认值、纯判断、公共路径 |
| `draw_flow.py` / `proactive_chat.py` | 生图调度与恢复；主动闲聊、跟随、关键词取材 |
| `prompts.py` / `reply_text.py` | 模型提示词；回复排版、截断和隐私过滤 |
| `attachments.py` | 附件限额、GIF 抽帧、请求独立的来源信息、最近图片与等待补图 |
| `memory_store.py` / `memory_service.py` | SQLite 群/成员记忆、时间线、证据与修订；按会话召回及管理员手动整理 |
| `meme_library.py` / `meme_collection.py` | 本地表情候选、限频与发送前校验；同群表情收藏、去重和清理 |
| `cache_maintenance.py` | 受管缓存和过期附件清理 |
| `runtime_status.py` | 白名单状态快照与原子写入 |
| `jimeng.py` / `image_jobs.py` | 即梦 CLI；生图进度、恢复与自拍保留 |
| `image_job_commands.py` | 当前会话生图任务查询、管理员确认与补发 |
| `request_queue.py` | 问答排队和远端任务占用 |
| `source_files.py` | 热重载、版本检查、语法检查及打包共用的源码清单 |

新增源码模块时需更新 `source_files.py`。生命周期与后台任务仍由主插件管理；面板配置在调用模块时传入。`draw_sessions.json` 保存一人一框映射，不随部署材料分发。GIF 读取使用 Pillow，插件的 `requirements.txt` 声明此依赖。

## 常用入口

| 操作 | 入口 |
|---|---|
| 启动机器人 | 根目录的 `start-astrbot.bat` 与 `start-napcat.bat` |
| 检查运行状态 | `scripts/doctor.bat` |
| 开始 / 停止 / 查看记忆整理 | `scripts/memory-control.bat --start` / `--stop` / `--status` |
| 刷新 WorkBuddy 连接 | `scripts/reconnect.bat` |
| 重载自制插件 | `scripts/reload-plugin.bat` |
| 暂停 / 恢复 QQ 中转 | `scripts/pause-bridge.bat` / `scripts/resume-bridge.bat` |
| 运行当前包的离线检查 | `scripts/test-bridge.bat`，会显示完整回归或仅部署自检 |
| 重置面板密码 | `scripts/reset-astrbot-password.bat` |
| 修复启动脚本编码 | `scripts/fix-bat-encoding.bat` |

维护工具从自身位置定位项目根目录，双击或从其他工作目录启动都使用本项目的环境与文件。详细安装步骤见 [部署指南](docs/部署指南.md)。

WorkBuddy 网关端口动态发现：先验证凭据文件提供的端口与上次成功地址，均失败后才扫描本机回环端口；失败后的 30 秒退避只限制全量扫描。端口线索或凭据更新后立即允许重新扫描，不需要等待退避结束。密码也变化时，仍需在能获得新凭据的 WorkBuddy 会话中运行重连工具。

## 使用与边界

群里通过 @、引用或已配置的唤醒词提问；私聊仅接收管理员。普通成员请求操作电脑时先待审批，由管理员在原群确认；管理员可以用“/执行 具体任务”显式发起操作。获批任务使用独立产出目录收集结果。

明确 @ 机器人时，即时文字回复默认使用 QQ 原生引用，指向本条提问的消息标识；@全体、私聊、戳一戳、缺少有效标识或不支持引用时按普通回复处理。主动闲聊和异步生图结果沿用原发送路径，引用显示不改变 WorkBuddy 的上下文隔离能力。

自动表情与同群收藏默认开启。人工素材放在 `表情包/` 顶层，可供各群使用；自动收藏仅在来源会话使用，按 QQ 的自定义表情标记识别，并非视觉分类，照片被当作自定义表情发送时也会收录。每轮按当前消息与本群近期话题召回候选，取消原来的 20% 随机门槛，由同一次模型请求决定是否发送；轻松短互动可只回一张表情，认真问题仍需文字回答。每轮最多学习一张未命名图，看清后自动记录名称与用途标签，已命名图按语义复用。名称存于图片旁 `.names/`，图片保留原文件名与指纹去重。默认同群间隔 120 秒、全局 20 秒、同图 10 分钟；已保存的面板间隔继续生效。收藏单图不超过 10 MiB，每群最多 100 张、全局最多 500 张且不超过 100 MiB，30 天未再出现的收藏及其名称记录定期清理；人工素材不参与收藏清理。开关与验收方法见部署指南。

问答使用 WorkBuddy 的任务通道，会进入桌面端共享会话。插件随请求提供本群上下文，并核对一次性回执；这不构成模型内部会话隔离，也不构成操作系统级权限隔离。管理员的普通聊天不等于执行授权。

长期记忆由桥接层独立管理，保存在插件目录的 `memory.sqlite3`，不依赖 WorkBuddy 的会话保存；数据库及其 WAL/SHM 文件，以及本机的 `memory_control.json`、`memory_control.processing.json` 控制请求，都不随部署包分发。记录以平台实例、机器人账号和群聊/私聊为第一层，以发言成员为下一层。同一个人在不同群不自动共享，昵称变化不改变归属。每个群保留有来源支持的共同话题、活动或约定，成员的偏好和个人近况保存在该群下的独立记忆里。普通问答只召回提问者本人的资料及相关群记忆；主动闲聊按人物标注相关同群资料。记忆不改变管理员身份和执行审批。

查看群层目录用 `/群记忆`，展开共同主题用 `/群记忆 主题名`，全部群条目用 `/群记忆 全部`；群目录显示简短介绍和成员记忆统计，不展开别人的个人档案。查看自己在当前群的子目录用 `/记忆`，展开主题用 `/记忆 主题名`，查看全部个人条目用 `/记忆 全部`。内容较多时按提示加页码，例如 `/群记忆 目录 2` 或 `/记忆 饮食偏好 2`。正常聊天无需这些命令；明确补充可在原群 @ 机器人后发送 `记住：我不吃香菜`，更正用 `/更正记忆 编号 新内容`，删除用 `/忘记记忆 编号`，清除本人的原文和记忆用 `忘掉我的全部记忆`。个人命令只操作本人；群记忆由后台按来源整理，不通过这些个人命令直接写入。`/重置` 仍只重置聊天上下文。

消息先收录、后整理：每次收到可确认来源和消息标识的人类消息，先按群、成员、原消息时间和接收时间写入 SQLite，同时用本地规则标注消息类型（闲聊、问句、命令、媒体、角色扮演或超长）和主题线索（偏好、计划、自述或其他）。这些标签只是原消息分类，不等于已核实的长期事实，不调用模型，也不会直接生成记忆。schema 4 为旧记录补充中性默认标签，原文、可提炼标记和遗忘屏障保持不变。每条文字最多保留 1000 字，原文保留七天，每个会话最多 2000 条；命令、角色扮演和超长片段可保留为非提炼记录。纯媒体消息只记类型占位，不为记忆额外下载附件。角色状态检查不会因普通群聊而续期。

模型整理只能由管理员手动开启，平时只收录、分类和召回已有记忆。QQ 入口为 `/整理记忆 开始`、`/整理记忆 停止`、`/整理记忆 状态`；本机入口为 `scripts/memory-control.bat --start`、`--stop`、`--status`，对应 Python 脚本也接受相同参数。每次开启只处理启动时已经积压的消息；之后收到的新消息继续入库，留给下次手动整理。本轮完成后自动结束，重载或重启不会自行恢复模型整理。

启动前，管理员先确认其他 WorkBuddy 窗口没有任务。程序会检查本插件的问答、生图和待审批任务，以及当前网关的状态；每批提交前再检查一次。现有公开接口不能保证全桌面所有会话在同一时刻均空闲，因此不能仅凭本插件队列为空就断言全局空闲。有新的前台任务时结束本轮，由管理员在空闲后重新开启；停止请求不会强杀已提交的远端批次，会保留跟踪并在当前批次收尾后停止。

每批以一名成员的待整理原话为主，并附同一群按时间排列的相邻发言；两者都受本轮启动时的消息上界限制，明确标注作者与时间。一次请求同时筛选个人记忆和群记忆，沿用原有 WorkBuddy 队列与普通聊天权限。整理使用专门的内部 JSON 提示词，不套用 QQ 聊天人设、静默或先搜索规则；一次性回执和当前批次的 proof 分别校验。来源文字只作材料，不授予工具或电脑操作权限。没有候选也必须返回带正确 proof 的空数组。

个人事实不再要求以“我／本人／叫我”开头，但仍必须由本人完整原话支持；问题、假设、转述和指向其他人的内容不能直接写成本人事实。群记忆需要至少两名成员的原话支持，不把单人的喜好当作全群共识。内容保存经核验的完整原话及必要上下文来源，不接受模型凭空改写的事实；每条事实原文不超过 300 字，不确定或无长期价值时跳过。原始待办和退避时间持久保存，重启后仍需管理员重新开启一轮整理。

整理诊断区分保存成功、合法空候选、候选被过滤或无变更，以及网关、忙碌、状态待确认、静默、格式与证据校验失败；零条入库也记录固定结果类别和计数，不再把这些情况统一归为 JSON 格式错误。消息收录数量不等于长期记忆数量，实际产出仍需更新后观察。

群记忆和个人记忆均可按主题归组，每组有一句简短介绍，依据当前有效条目生成并参与检索。更正、遗忘或到期后介绍同步更新，空组自动消失。同组不同事实有独立专题，不相互覆盖。数据库自动迁移现有记录，无需重建。

保存期限分为稳定偏好、稳定自述和近期话题；近期话题七天过期，稳定资料保留至更正或遗忘，每个会话最多 500 条有效记忆。更正保存修订，明确保存的个人条目不被自动整理覆盖。遗忘会删除相应内容、证据和修订，并清除本人的旧原文；依赖这些原话的群记忆和上下文引用也失效，旧批次不能重新写回。每小时清理过期原文和话题。面板 `memory_enabled` 控制采集和召回；关闭后仍可查看和忘记已有记忆。`memory_auto_extract` 仅作为历史配置兼容保留，默认关闭，即使旧配置仍为 true 也不会自动发起模型整理。数据库异常时记忆功能退避一分钟。以上会话范围只覆盖桥接层提供的资料，不改变 WorkBuddy 内部上下文行为。

QQ 问答默认同时处理一条，最多等待 5 条，等待上限 60 秒；普通提问和已批准的执行任务按进入队列的顺序处理。主动闲聊不进队列，繁忙时跳过；从取材起默认 30 秒内未能完成，或其间群里已有新消息，则不补发旧话题。已提交到 WorkBuddy 的任务不能被本地队列抢占。

本地超时、维护或重载并不证明 WorkBuddy 的任务已结束。插件会把必要的任务编号保存在 `question_run.json`（无提示词和凭据），查询明确结束后才提交下一条。若提交结果不明、状态查询失败或网关地址变化，则保留记录并提示状态待确认。管理员确认 WorkBuddy 上一轮确实结束后，可发送 `/恢复问答 确认上一轮已结束` 清除占用；这条指令不会终止远端任务。不要在旧任务仍运行时使用。普通成员不能清除记录。

主动闲聊因连续网关错误停用后，一次普通问答在回执校验通过、远端任务明确结束并清除占用后，会自动恢复主动闲聊。获批执行、校验失败、远端状态不明及排队跳过不会触发恢复。

即梦调用链是 QQ → 桥接插件 → `jimeng.py` → `dreamina.exe`，无需启动即梦反代网页服务。CLI 路径依次使用面板 `image_gen_bin`、环境变量 `QQ_BOT_DREAMINA` 和原有默认位置；CLI 自己管理登录状态。生图保留一人一框、冷却和面板配置；任务在提交前保存到插件的 `draw_jobs/`，拿到任务号后只查询原任务。重载后在原生成时限内恢复查询，仍有本地副本的图片只补发至原群，明确发送失败最多尝试三次；提交或发送结果不明时暂停自动重试。会话准备、提交、查询和下载共用生成超时，单次 CLI 调用最多 30 秒，回图每次最多 20 秒。已生成图片的恢复窗口为 24 小时，暂停或未确认机器人账号时不发送。会话改名在交付后进行。

附件单文件和单条消息原始附件总量均限制为 10 MiB（界面称 10 MB），最多 5 个。单个附件取文件最多 15 秒，整批处理最多 30 秒；超限、超时或解析失败会明确提示。普通附件的初始下载由框架提供，桥接层在可获知大小时提前拒绝，并对接收到的文件及复制过程再次核验；这不代表修改了框架的下载器。GIF 保留原文件，另生成最多 8 张时序抽帧组成的预览，单份预览不超过 1 MiB；模型看到的是抽样画面，不能保证识别全部动作或精确时长。主动闲聊的图片下载也有 10 MiB 流式上限，并复用 GIF 处理。

群里先 @ 机器人，再发送 `/生图任务` 或 `/生图任务 任务号`；普通成员仅能查看本会话自己的任务，管理员能查看本会话全部任务。管理员核实后可发送 `/生图处理 任务号 确认已送达`、`/生图处理 任务号 补发确认` 或 `/生图处理 任务号 结束`。补发只使用原任务已有图片并发回原会话，不会重新生图；同一条补发消息不会重复执行，每个任务最多人工补发三次。已送达和已人工结束的任务不会再次补发。

本地生图只长期保留机器人自己的自拍：由“你的照片/自画像”专用入口生成的任务在提交前写入保留标记，普通画图即使提示词提到自拍也不会自动保留。普通图正常送达、管理员确认送达或人工结束后，清理任务记录对应的本地图片；发送失败或结果待确认的副本暂存至任务的 24 小时恢复窗口结束，随后由定期维护清理。清理失败会重试，记录、原始远端任务号和即梦网页端均不删除；本地副本清理后不能再用补发指令发送。

旧任务有准确的自拍提示词标记时继续保留自拍、清理可识别的普通图。没有任务记录的旧平铺图片无法可靠分类，保守保留；其他任务产出和用户手动放入的文件不参与清理。修改生图目录配置后需重载插件，使新的可信清理目录生效。

已送达、失败、过期或人工结束的任务在最后更新超过 30 天后归档到 `draw_jobs/archive/年月/`；每小时维护最多检查 100 条，轮转处理。进行中和结果不明的任务不归档；图片按下面的保留规则单独清理，锁文件保留以维持跨进程互斥。聊天查询显示尚未归档的记录。

缓存维护在插件加载后执行一轮，之后每轮结束间隔一小时再次执行，不依赖群消息或闲聊开关。收到的附件保留两天；`AstrBot/data/temp` 顶层和 `idle_pics` 直属文件保留一天，媒体每轮最多删除 2000 个过期文件。其他临时子目录和用户产出不在清理范围内，链接及重解析路径跳过。日志中的 `managed_remaining` 只统计这两个媒体目录，不代表整个 temp 目录树。插件卸载时先通知清理线程停止并等待结束。

同机部署时，6199 对应的 QQ 反向 WebSocket 监听地址应为 `127.0.0.1`，NapCat 连接 `ws://127.0.0.1:6199/ws`；修改监听配置需要重启 AstrBot。跨机器部署应按实际连接方式配置。

插件开启热重载后，修改 `source_files.py` 清单中的源码文件会触发重载，包括提示词和回复过滤模块。重载工具会核对新实例与完整源码指纹。PASS / VERIFIED 只表示相应检查有证据通过；UNKNOWN 表示证据不足。doctor、reconnect、reload-plugin 使用退出码 0、1、2 分别表示已确认、失败和证据不足。

插件初始化完成后，每 30 秒更新本机 `bridge_status.json`，退出时标记为已停止。它只保存版本、实例、连接状态、排队数量、占用原因和固定结果类别，不保存提示词、群号、任务正文或凭据。其中 `memory` 摘要提供整理状态、尝试和保存计数、最近一批的结果与过滤原因计数；只接受白名单状态和数值，不含聊天原文、记忆内容或成员身份。计数从本次插件启动开始；若提交途中被取消、结果尚未确认，省略无法确认的保存数，不把它记成零。检查工具将 90 秒内的运行心跳与版本证据分开判断，正常运行超过五分钟不会仅因启动时间较早而变成未知；心跳过期、停止或损坏则不能确认存活。状态显示最多可能滞后一个心跳周期，不代表 QQ 收发或新一轮生成已经验收。该文件不随部署包分发。

## 测试与打包

源码目录或开发包可在项目根目录运行：

```bat
.venv\Scripts\python.exe -B -m unittest discover -s tests -p "test_*.py" -v
.venv\Scripts\python.exe -B tests\bridge_selftest.py
```

`bridge_selftest.py` 是统一入口，检查按职责放在 `tests/selfcheck/`。默认运行包保留这套部署自检，完整开发回归保留在源码目录及开发包。所有检查使用模拟服务和临时文件，不调用真实模型、生图或向 QQ 发送消息。测试分类见 [tests/README.md](tests/README.md)。

维护者构建部署材料：

```bat
.venv\Scripts\python.exe scripts\build-material.py
.venv\Scripts\python.exe scripts\build-material.py --development
```

文档源文件保存在 `docs/`。默认命令生成 `dist/QQbot部署材料/` 及同名 ZIP，包含运行所需插件、维护入口和部署自检；`--development` 生成 `dist/QQbot开发材料/` 及同名 ZIP，另含完整开发回归。两种包都保持相对目录结构，完整部署指南只保留在包内 `项目根文件/docs/`，包根 README 提供入口。不要直接编辑生成目录；已有完整开发测试的项目应使用开发包更新，避免代码与测试版本不一致。两种包均不包含第三方程序、凭据、聊天记录、历史备份或构建脚本中的本机脱敏对照。
